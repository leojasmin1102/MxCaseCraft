# CAE 对标测试套件

将“某个自研 CAE 功能对标某个参考求解器的关键字或功能”的需求转化为可执行、可回归的测试资产。支持 Nastran、Abaqus、OptiStruct 及用户指定的其他 CAE 求解器。默认使用中文撰写专业说明，仅保留关键字、字段名、单位和文件名等必要英文。

## 接收输入

从用户请求中提取：待验证需求、参考软件及版本、关键字/语法、所属模块、测试用例范围、测试用例类型、求解范围、单位制、已有算例/脚本、输出目录及当前确认的用例编号。

若缺少所属模块，使用“CAE关键字对标”并在最终回复中说明；若未说明参考软件，先询问，或仅生成不绑定语法的功能级测试规格。若缺少会改变物理含义的条件（例如单位制、非线性能力或目标求解类型），先简短询问。其余内容采用合理且明确的默认值。

若未指定“测试用例范围”，默认使用“全部用例”。其可选值为：

- `有效功能用例`：仅生成 `Txx` 正向功能、数值正确性与兼容性用例；
- `异常输入与诊断用例`：仅生成 `Dxx` 非法输入、冲突定义、缺失引用与诊断用例；
- `全部用例`：同时生成 `Txx` 与 `Dxx` 用例。

“测试用例类型”用于选择需要输出的测试类别，可与“测试用例范围”组合使用。可选值为：

- `有效功能用例`：输出 `Txx`；
- `异常输入与诊断用例`：输出 `Dxx`；
- `其他类型用例`：输出用户指定的其他类别，例如性能、兼容性、安装部署、安全或回归；必须同时提供类型名称和验收目标；
- `全部类型`：输出有效功能、异常输入与诊断，以及用户明确指定的其他类别。

若未指定“测试用例类型”，根据“测试用例范围”生成有效功能和/或异常输入与诊断用例，不擅自添加其他类别。若只指定“其他类型用例”或“全部类型”但未说明其他类型的名称和验收目标，先询问。

原生算例和 HyperMesh Tcl 采用强制“逐项确认”模式：首次请求不生成任何原生输入文件或 Tcl；用户每次确认一个已列出的用例编号后，只生成该编号对应的一组算例与 Tcl。不得因用户选择“全部用例”或“全部类型”而批量生成，亦不得将“请继续”或“全部确认”视为多项确认。

## 执行流程

1. 核对参考软件的关键字定义、字段、默认值、限制条件和结果输出；优先使用该软件的官方文档。不要把一种求解器的语法、默认值或单元行为推断给另一种求解器。
2. 将需求拆为最小、相互独立的测试用例。每项能力至少覆盖输入读取、模型建立、求解结果和结果恢复；按需增加导入导出、动力学和异常输入用例。拆分后先按“测试用例范围”筛选有效/异常用例，再按“测试用例类型”合并或排除类别。
3. 为每个有效用例写出可计算的预期结果：给定参数、解析公式、数值结果、容差和应检查的输出量。异常用例必须给出预期诊断和禁止行为。
4. 首次请求时，生成测试规格、用例清单及两份 Excel 表，并逐项列出候选用例的编号、目的、关键输入、预期结果和生成顺序；在收到用户对一个具体用例编号的确认前，禁止生成原生算例或 Tcl。
5. 收到用户确认的单个用例编号后，生成该编号对应的参考软件最小原生算例：Nastran 使用 `BDF/DAT`，Abaqus 使用 `INP`，OptiStruct 使用 `FEM` 或其实际支持格式。每个算例只验证一个主要行为；补足必要约束以消除刚体自由度；在文件注释中写明单位和预期结果。异常用例可仅提供用于校验或导入的最小输入，不得伪造可求解模型。
6. 仅为已确认用例生成其 HyperMesh Tcl。优先采用“脚本写出原生求解器输入文件，再调用 HyperMesh 对应读入器”的方式，避免不同版本的卡片字段名差异。脚本必须：
   - 不清空或覆盖用户已有模型；
   - 在非空模型中安全退出；
   - 避免覆盖已有 BDF/HM 输出；
   - 保存生成的 BDF 和 HM 模型，并在控制台输出校核值。
7. 生成两份 Excel 文件。创建或编辑 Excel 时必须使用 `spreadsheets` skill，按其渲染和公式校验流程交付。
8. 在可用时运行已确认用例的 HyperMesh 批处理验证 Tcl 导入；检查原生输入文件关键字、文件存在性和脚本输出。仅在相应参考求解器已安装且用户允许时运行求解器。不要把批处理正常退出时的外壳退出码单独作为失败依据，应以脚本成功信息和文件结果判定。完成后报告该用例的结论，并等待用户确认下一个具体编号。

## 固定交付物

为每次任务建立一个以关键字命名的目录，至少输出：

1. `测试规格_<关键字>.md`：测试目的、前置条件、步骤、预期结果、容差和判定规则；
2. `算例/<参考软件>/`：仅包含经用户逐项确认后生成的最小原生输入文件，必要时附预期结果说明；
3. `脚本/`：仅包含经用户逐项确认后生成的 Tcl；
4. `禅道测试用例_<参考软件>_<关键字>.xlsx`：符合本 skill 定义的禅道列顺序；
5. `测试结果统计_<参考软件>_<关键字>.xlsx`：预置全部用例、预期摘要、状态下拉和自动汇总；
6. `验证记录.md`：记录已实际运行的脚本/导入检查及其结论。

如用户只要求其中一部分，仍保持用例编号和预期结果的一致性，不强制创建无关文件。所有已生成文档、脚本、算例和表格中的用例编号、数量与类别必须与“测试用例范围”和“测试用例类型”一致；被排除的类别不得残留。

## 逐项确认与交付状态

- 将测试规格、禅道表和统计表中的全部选定用例标记为“已规划”；它们不表示对应算例或 Tcl 已生成。
- 将已由用户确认并实际生成原生算例与 Tcl 的单个用例标记为“已生成”；仅在完成检查后标记为“已验证”。
- 每轮只处理一个明确编号。生成完成后，汇报该编号的文件、检查结果和限制，再等待下一项确认。
- 用户确认不存在于已规划清单中的编号时，先更新测试规格和表格并请其确认更新后的该项，不直接生成文件。

## 用例设计规则

- 使用 `T01`、`T02`… 编号表示有效功能用例；使用 `D01`、`D02`… 表示异常输入与诊断用例。
- 其他类型用例使用不与 `Txx`、`Dxx` 冲突的类型前缀；默认可使用 `O01`、`O02`…，并在测试规格和统计表中明确类型名称。用户指定前缀时优先使用其规则。
- 将“读取成功”与“数值结果正确”分别断言；不要仅用“求解未报错”作为通过条件。
- 对每个线性基础用例，至少检查位移、约束反力或平衡力、单元力和应变能中的适用项。
- 对连接/离散单元，增加串联、并联、端点交换和坐标系用例，以检出装配与结果符号错误。
- 对动力学能力，采用单自由度模型并给出解析频率或频响幅相；对阻尼必须明确阻尼模型。
- 对非法输入，明确期望错误实体、字段和错误原因；禁止软件静默补默认值、自动加约束或改写用户输入。
- 通过数值容差应与分析类型匹配。解析静力推荐相对误差不大于 `1e-6`；模态推荐 `1e-5`；频响幅值推荐 `1e-4` 且相位误差不大于 `0.1°`，除非用户另行规定。

## 测试用例范围控制

“测试用例范围”必须一致地控制所有交付物，不能只筛选其中一个表格：

- 选择 `有效功能用例` 时，测试规格、原生算例、Tcl、禅道表和统计表中仅保留 `Txx`；汇总仅统计 `Txx`。
- 选择 `异常输入与诊断用例` 时，上述交付物中仅保留 `Dxx`；预期以拒绝、错误级别、定位信息和诊断关键词为主，除非异常用例本身可安全求解。
- 选择 `全部用例` 时，同时输出两类用例，并在统计表中保留类别字段，以便分别筛选和汇总。

## 测试用例类型控制

“测试用例类型”在范围筛选后统一控制所有交付物：

- 选择 `有效功能用例` 时，仅输出范围内的 `Txx`；
- 选择 `异常输入与诊断用例` 时，仅输出范围内的 `Dxx`；
- 选择 `其他类型用例` 时，仅输出用户定义的其他类型及其 `Oxx`（或用户指定）编号；
- 选择 `全部类型` 时，输出范围允许的 `Txx`、`Dxx`，以及用户明确要求的其他类型。

当“测试用例范围”与“测试用例类型”冲突时，以两者的交集为准；例如范围为“有效功能用例”且类型为“全部类型”时，只输出 `Txx` 和用户明确要求的其他类型，不能输出 `Dxx`。其他类型不受“有效/异常”范围限制，但必须有用户提供的名称和验收目标。

## 禅道和统计表

读取 [references/zentao-and-statistics.md](references/zentao-and-statistics.md)，严格使用其中的列顺序、下拉值和填写规则。用户给出所属模块时，填入禅道表的“所属模块”列；若用户明确要求自行填写该列，则保持为空。

## 多求解器对标路由

先读取 [references/reference-solver-routing.md](references/reference-solver-routing.md)，选择与参考软件一致的输入格式、HyperMesh 用户配置文件和结果检查点。

若需求是“将 Abaqus/OptiStruct 功能与 Nastran 关键字对标”，先定义共同的物理行为、自由度、参数、载荷、边界条件和可比输出量；再为每个参考软件分别生成原生算例。比较统一物理量，不要求不同求解器的关键字或结果字段名称相同。

## CELAS1 专用基线

当对标目标为 Nastran `CELAS1`，或 OptiStruct 明确支持兼容的 `CELAS1` 语义时，先读取 [references/celas1-baseline.md](references/celas1-baseline.md)。以该基线作为起点，并根据用户的产品范围增删用例。若使用 Abaqus 或其他求解器实现同等弹簧行为，保持基线中的物理预期，但必须以该软件的原生关键字和官方定义建模。尤其不要把 CELAS1 误建模为沿两节点连线自动定向的几何弹簧。

## 交付前检查

- 用例规格、BDF、Tcl、禅道表和统计表的用例编号必须一一对应；
- 用例编号和类别必须完全符合选定的“测试用例范围”和“测试用例类型”；
- 未经用户逐项确认的用例不得存在原生算例或 Tcl；
- 所有 BDF 应有单位、载荷、约束与预期数值注释；
- 所有可计算的预期结果应已手工复核；
- Excel 表中下拉值、公式、列标题和中文换行应已渲染检查；
- 最终回复简洁列出完成的交付物、验证结论和任何未验证限制。
