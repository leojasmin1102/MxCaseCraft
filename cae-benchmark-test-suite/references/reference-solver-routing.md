# 参考求解器路由规则

## 共同原则

先确定“对标什么”：关键字读取兼容性、物理行为等价性、结果输出一致性，或三者兼有。不同求解器即使实现同类功能，也不得假设字段名、默认值、阻尼定义、局部坐标系或单元力正方向相同。

对跨求解器对标，固定以下共同量：单位制、节点/自由度、材料或属性参数、约束、载荷、分析类型、结果采样位置和容差。优先比较位移、反力、能量、频率、频响幅相等物理量。

## Nastran

- 原生输入通常为 `BDF` 或 `DAT`；
- 核对 Bulk Data、Case Control、`F06/OP2` 输出请求；
- 使用 HyperMesh 的 Nastran 用户配置文件和读入器；
- 当目标为 `CELAS1` 时读取 `celas1-baseline.md`。

## Abaqus

- 原生输入为 `INP`；
- 核对 `*KEYWORD` 的数据行、集合、分析步、输出请求和局部坐标系；
- 使用 HyperMesh 的 Abaqus/Standard 或 Abaqus/Explicit 对应用户配置文件和读入器；
- 若对标弹簧、连接器或阻尼功能，必须核实原生关键字、自由度定义和阻尼模型，不得直接复制 Nastran 的卡片字段。

## OptiStruct

- 原生输入通常为 `FEM`，其许多条目与 Nastran 类似但不必然完全等价；
- 使用 Altair 官方 OptiStruct 文档核对每个条目的支持范围、参数含义与默认值；
- 使用 HyperMesh 的 OptiStruct 用户配置文件和读入器；
- 只有在官方文档明确支持兼容语义时，才能复用 Nastran 基线的关键字级断言；否则仅复用物理行为和结果级断言。

## 其他求解器

用户提供求解器名称、版本和关键字后，优先查找该软件的官方参考手册。若无法获得可靠语义，只生成测试框架、待确认字段和需由用户确认的预期项，不编造数值或语法。
