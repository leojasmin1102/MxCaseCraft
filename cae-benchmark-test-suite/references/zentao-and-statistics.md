# 禅道用例表与结果统计表规则

## 禅道测试用例表

按以下固定顺序输出列：

| 列 | 名称 | 填写规则 |
| --- | --- | --- |
| A | 所属模块 | 使用用户提供的模块；若用户要求自行填写则留空。 |
| B | 用例名称 | 以“验证……”开始，准确描述被验证能力。 |
| C | 前置条件 | 写清模型、参数、约束、版本和输入文件。 |
| D | 步骤 | 逐行编号；包含导入、施加条件、求解和结果查看。 |
| E | 预期 | 写可观察、可判定的数值结果或错误行为。 |
| F | 关键词 | 以中文分号分隔关键字、字段和能力。 |
| G | 优先级 | 下拉值：`1`、`2`、`3`、`4`；1 为最高优先级。 |
| H | 用例类型 | 下拉值：`接口测试`、`功能测试`、`安装部署`、`配置相关`、`性能测试`、`安全相关`、`其他`。 |
| I | 适用环节 | 下拉值：`单元测试环节`、`功能测试环节`、`集成测试环节`、`系统测试环节`、`冒烟测试环节`、`版本验证环节`。 |

将基础解析、静力和关键异常输入通常标为优先级 1；动力学、回归和边界行为通常标为优先级 2，除非用户另有风险分级。

## 用例范围筛选

生成表格前，先读取主流程的“测试用例范围”和“测试用例类型”，并与测试规格、原生算例和 Tcl 使用同一份筛选结果：

- `有效功能用例`：仅写入 `Txx` 用例；
- `异常输入与诊断用例`：仅写入 `Dxx` 用例；
- `全部用例`：写入 `Txx` 与 `Dxx` 用例。

随后按“测试用例类型”再次筛选：选择有效功能或异常输入与诊断时仅保留对应编号；选择其他类型时仅保留用户定义的其他类别；选择全部类型时保留范围允许的 `Txx`、`Dxx` 及用户明确要求的其他类别。其他类型的编号默认使用 `Oxx`，并在“用例类型/用例类别”列填写具体名称。

不得为了保留模板而写入不在选定范围内的空白用例行。A 列若由用户填写则保持空白；其他列仍应完整写入所选用例内容。

测试规格、禅道表和统计表可一次列出所有已规划用例，但不得据此批量生成原生算例或 Tcl。建议在统计表“备注”或新增“交付状态”列中标记 `已规划`、`已生成`、`已验证`：仅当用户确认具体用例编号后，才将该编号更新为 `已生成` 或 `已验证`。

## 测试结果统计表

预置与禅道表完全相同且处于选定范围内的用例编号。至少包含：

- 用例编号、用例名称、用例类别、对标对象、预期结果；
- 实测关键结果、相对误差、执行日期、执行人、测试状态、缺陷编号、结果文件或路径、备注；
- 自动统计用例总数、通过数量、失败数量、阻塞数量、未测试数量和通过率。

“测试状态”下拉值固定为：`未测试`、`通过`、`失败`、`阻塞`、`不适用`。用条件格式突出通过、失败和阻塞状态。汇总公式仅统计由“测试用例范围”和“测试用例类型”共同选定的明细；选择“全部用例”或“全部类型”时，保留“用例类别”列，以支持按有效功能、异常诊断及其他类型分别筛选和统计。
